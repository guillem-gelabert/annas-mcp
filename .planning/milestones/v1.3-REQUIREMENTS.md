## v1.3 Requirements

### API Shape

- [x] **API-01**: `article_download` accepts either `doi: string` (existing) or `dois: string[]` (new) as mutually exclusive inputs; both are validated with the existing DOI regex
- [x] **API-02**: When `dois` is provided, the response returns an array of per-article results (article metadata, sources, optional filePath); single-DOI response shape is unchanged

### Batch Execution

- [x] **BATCH-01**: Multiple DOIs are resolved in parallel (concurrent `lookupArticleByDoi` calls)
- [x] **BATCH-02**: File downloads within a batch run in parallel when `download: true` is set
- [x] **BATCH-03**: Each article result in the batch response includes its own success/error state, so one failure does not suppress successful results

### Circuit Breaker — base_url

- [x] **CB-01**: The first `base_url` resolution failure within a batch triggers exactly one re-discovery attempt (not once per article)
- [x] **CB-02**: If re-discovery succeeds, remaining DOIs resume with the new mirror URL
- [x] **CB-03**: If re-discovery fails, all remaining unresolved DOIs fast-fail with a clear error (no further re-discovery retries)

### Circuit Breaker — CDN domain_index

- [x] **CB-04**: A shared per-host denylist accumulates CDN host failures across the batch
- [x] **CB-05**: When a CDN host is added to the denylist, in-flight requests to that host are aborted via `AbortController`
- [x] **CB-06**: Subsequent articles skip denylisted hosts and proceed directly to the next `domain_index` or scidb fallback
- [x] **CB-07**: Single-DOI path is unaffected — existing domain_index loop behavior is preserved

### Backwards Compatibility

- [x] **COMPAT-01**: Existing `doi: string` callers receive identical response shape and behavior as today
- [x] **COMPAT-02**: No new MCP tool is registered — tool count stays at 5

### Phase 14 — Codex Review Remediation

- [x] **REM-01**: Batch mode honors a manually configured `ANNAS_BASE_URL` (no silent rediscovery); single-DOI and batch-DOI behave identically under this configuration
- [x] **REM-02**: Refreshed `baseUrl` propagates to any lookup entering after a successful rediscovery
- [x] **REM-03**: Batch downloads are safe under duplicate titles/DOIs — per-attempt UUID-suffixed temp file plus in-batch filename reservation
- [x] **REM-04**: CDN host denylist triggers only on host-level errors (`NETWORK`, `HTTP_5XX`, local-timeout `TIMEOUT`); article-level errors (bad PDF magic, size limit, HTML body, local IO) do not denylist
- [x] **REM-05**: Download timeout covers the full body read and rename, not just response headers
- [x] **REM-06**: Stream error cleanup follows a single rejection path; no leftover `.tmp` file remains after invalid-PDF / oversize / truncated outcomes

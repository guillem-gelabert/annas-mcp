# Milestone v1.3: Batch Article Download

**Status:** ✅ SHIPPED 2026-05-21

## Overview

Extended `article_download` to accept a single DOI or a list of DOIs, with parallel URL/metadata resolution and batch-scoped circuit breakers. Phase 14 closed all seven findings from the codex review: manual `ANNAS_BASE_URL` honored in batch, baseUrl propagation after re-discovery, filename-collision safety, host-level-only CDN denylist, full-body timeout, and single-rejection stream cleanup.

## Milestone Summary

**Decimal/Inserted Phases:**

- Phase 14: Codex Review Remediation (inserted after Phase 13 for codex review gap closure)

**Key Decisions:**

- `doi` and `dois` are mutually exclusive inputs; handler normalizes both to an internal array
- Two-stage `Promise.allSettled` pipeline: lookups fully settle before downloads begin
- Circuit breakers are batch-scoped only (not persistent across MCP calls)
- Base URL CB: `rediscoveryPromise` deduplication — exactly one re-discovery per batch
- CDN denylist: `AbortController` per in-flight request for graceful abort
- Manual `ANNAS_BASE_URL` wins and skips re-discovery in batch mode (same semantics as single-DOI)
- Phase 14 executed directly from codex review findings (no GSD discuss/plan cycle)

**Issues Resolved:**

- Manual `ANNAS_BASE_URL` was silently triggering re-discovery in batch mode
- Concurrent batch downloads with duplicate titles could race on temp file names
- Download timeout was header-only; body + rename were unbounded
- CDN denylist was triggering on article-level errors (bad PDF, HTML body) — too aggressive

**Issues Deferred:**

- None — all codex review findings closed in Phase 14
- Batch equivalent for `book_download` deferred to a later milestone if the pattern proves valuable
- CB-06 skip-path has determinism constraints in concurrent tests; covered implicitly via denylist accumulation proof

**Technical Debt Incurred:**

- None carried forward

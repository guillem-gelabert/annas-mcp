# Milestone v1.4: DOI Verification

**Status:** ✅ SHIPPED 2026-05-27
**Phases:** 15–17
**Total Plans:** 3

## Overview

Added CrossRef-based DOI cross-validation to `article_download`. Every download call now fetches the canonical paper title from CrossRef and compares it to the Anna's Archive title using Jaccard similarity. Low-confidence or unverifiable matches return `isError: true`, protecting callers from wrong-paper returns.

## Phases

**Goal**: A standalone CrossRef fetch function retrieves the canonical paper title for any DOI
**Depends on**: Nothing (new isolated module)
**Requirements**: VER-01, VER-02, VER-03
**Plans**: 1 plan

Plans:
- [x] 15-01: Implement fetchCrossRefTitle with TDD (failing tests then implementation)

**Details:**

Success criteria:
1. Calling the function with a known DOI returns the `message.title[0]` string from CrossRef
2. The outgoing request carries a descriptive `User-Agent` header (`annas-mcp-ts/1.4 (mailto:...)`)

### Phase 16: Confidence Logic

**Goal**: Given two title strings, the system produces a typed confidence level that callers can trust
**Depends on**: Phase 15
**Requirements**: VER-04, VER-05, VER-06
**Plans**: 1 plan

Plans:
- [x] 16-01: Implement computeConfidence with TDD (failing tests then implementation)

**Details:**

Success criteria:
1. Two titles with ≥ 0.5 Jaccard similarity on their normalised word sets return `"high"`
2. Two titles with < 0.5 Jaccard similarity return `"low"`
3. A null CrossRef title (timeout, non-200, missing field) returns `"unverified"` without throwing
4. Comparison is case-insensitive and strips punctuation before scoring

Key files created: `src/anna/confidence.ts`, `tests/confidence.test.ts`

### Phase 17: Response Integration

**Goal**: Every `article_download` response is gated on DOI verification confidence; no existing behaviour changes for unrelated tools
**Depends on**: Phase 16
**Requirements**: VER-07, VER-08, VER-09, VER-10, VER-11
**Plans**: 1 plan

Plans:
- [x] 17-01: Wire verification into single-DOI and batch handlers (TDD)

**Details:**

Success criteria:
1. Single-DOI `article_download` with high confidence returns `{ article, sources }` only
2. Low/unverified confidence returns `isError: true` with a descriptive message
3. Batch `article_download` gates each DOI individually; high → `{ doi, article, sources }`, low/unverified → `{ doi, error }`
4. CrossRef network failures are absorbed — `isError: true` on unverified, server never crashes
5. All 99 pre-existing tests continue to pass; 5 new verification tests added

Key files modified: `src/tools/article-tools.ts`, `tests/article-tools.test.ts`

**Note:** Phase 17 GREEN commit (`fd7bf2e`) implemented an additive `verification` field. The SUMMARY.md reflects the intermediate state; the verification behavior described here is the final delivered state.

## Milestone Summary

**Key Decisions:**

- `fetchImpl` is injectable (default: global fetch) for full test isolation — mirrors existing `AnnasClient` pattern
- Jaccard threshold 0.5 hardcoded (configurable deferred to future milestones)
- Hard-error gating model (not additive field) — low/unverified confidence → `isError: true`; this was upgraded post-Phase 17 to provide stronger caller guarantees
- `ConfidenceLevel` type inferred transitively in `article-tools.ts` rather than explicitly imported

**Issues Resolved:**

- Wrong-paper returns from Anna's Archive are now detectable: title mismatch produces a clear error
- CrossRef unavailability is absorbed at the handler boundary via `.catch(() => null)`

**Issues Deferred:**

- Configurable confidence threshold (currently hardcoded at 0.5 Jaccard)
- Author cross-validation (CrossRef also returns authors)
- `article_search` DOI auto-detection (parity with Go upstream)
- Explicit `import type { ConfidenceLevel }` in `article-tools.ts`

**Technical Debt Incurred:**

- `RequestInfo` type used in `tests/article-tools.test.ts:522` is not in scope for the project's TS config — `bun tsc --noEmit` warns; runtime unaffected

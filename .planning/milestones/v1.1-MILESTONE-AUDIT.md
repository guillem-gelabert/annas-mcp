## Tech Debt — Accumulated Warnings

### W1: WIKIPEDIA_SELECTOR constant never applied (WIKI-01)
**File:** `src/anna/base-url-manager.ts` line 15-16  
**Issue:** The `WIKIPEDIA_SELECTOR` CSS selector constant is stored in cache records and returned in `update_base_url` output but is never evaluated. Discovery uses a full-wikitext URL regex, not CSS selector evaluation.  
**Impact:** Tool output misleads callers about the extraction method. More permissive than documented (any `annas-archive.*` URL in the full article, not just the infobox cell). The 24-hour trust filter is the actual gating mechanism and works correctly.  
**Fix:** Either implement HTML parsing with the selector, or replace the `selector` field in output/cache with a `method: "wikitext_regex"` field.

### W2: readCache errors are silent (CACHE-04 partial)
**File:** `src/anna/base-url-manager.ts` lines 88-94  
**Issue:** `readCache()` catches all exceptions and returns `null`. A corrupted or unreadable cache file silently falls through to full Wikipedia discovery. CACHE-04 requires both read AND write failures to be surfaced.  
**Fix:** Surface read errors in the `update_base_url` output (add a `cacheReadError` field) rather than swallowing them.

### W3: Offline automatic retry — zero test coverage (TEST-01 partial, REC-03)
**File:** `src/tools/article-tools.ts` lines 179-198  
**Issue:** The `withResolvedBaseUrl()` retry path is the most complex recovery logic in the milestone and has no test coverage. No test simulates: article fetch failing in automatic mode → `updateBaseUrl()` triggered → retry with new URL.  
**Fix:** Add a test in `tests/article-tools.test.ts` that stubs `BaseUrlManager` to: resolve a URL, throw an offline error on first article fetch, return a new URL after `updateBaseUrl()`, succeed on retry.

### W4: Double-offline guidance gap (REC-03 partial)
**File:** `src/tools/article-tools.ts`  
**Issue:** When the retry URL (from automatic discovery) is also offline, the user receives a raw network error with no actionable guidance. Only the first offline detection triggers helpful messaging.  
**Fix:** Catch the retry failure and surface guidance (e.g., "Refreshed base URL also appears offline. Call update_base_url again later or set ANNAS_BASE_URL manually.").

### W5: No VERIFICATION.md artifacts (process gap)
**Phases:** 5, 6, 7  
**Issue:** No VERIFICATION.md files were produced during phase execution. The verifier workflow was configured to run but did not produce artifacts.  
**Impact:** Future audits cannot rely on phase-level verification history. Tech debt only — all features confirmed implemented by integration checker.

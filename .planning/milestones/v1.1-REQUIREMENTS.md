## v1.1 Requirements — Final Status

### Base URL Tool

- [x] **BASE-01**: MCP client can call `update_base_url` to refresh Anna's Archive base URL discovery.  
  *Outcome: Validated — `update_base_url` registered in server.ts, returns structured output.*
- [x] **BASE-02**: `update_base_url` returns structured output with selected URL, trusted candidates, skipped candidates, source page, checked-at timestamp, and revision evidence.  
  *Outcome: Validated — `updateBaseUrlOutputSchema` covers all fields.*
- [x] **BASE-03**: Server registers `update_base_url` alongside existing article tools without changing `article_search` or `article_download` schemas.  
  *Outcome: Validated — both tool groups registered; article schemas unchanged.*

### Wikipedia Discovery

- [x] **WIKI-01**: Server extracts candidate URLs from the Anna's Archive Wikipedia infobox URL cell.  
  *Outcome: Validated with note — implemented via full-wikitext regex (not CSS selector). WIKIPEDIA_SELECTOR constant is documentary only. Behavior is more permissive than intended but trust filter compensates.*
- [x] **WIKI-02**: Server normalizes discovered candidates into the same base URL format used by Anna's Archive client requests.  
  *Outcome: Validated — `normalizeBaseUrl()` strips scheme, trims slashes.*
- [x] **WIKI-03**: Server discards malformed, duplicate, non-http(s), and non-Anna's-Archive-looking links.  
  *Outcome: Validated — HOST_PATTERN regex + Set deduplication + https prefix filter.*
- [x] **WIKI-04**: Server trusts a candidate only when Wikipedia revision history proves it existed at least 24 hours before refresh time.  
  *Outcome: Validated — `latestRevisionSeen && seenBeforeThreshold` logic.*
- [x] **WIKI-05**: Server skips candidates whose 24-hour age cannot be proven within bounded revision-history scanning.  
  *Outcome: Validated — REVISION_LIMIT=200, LOOKBACK_MS=14d; `skippedReason: "not_seen_older_than_24h_or_unproven"` returned.*

### Cache and Selection

- [x] **CACHE-01**: Server persists trusted discovery results in a local JSON cache with evidence metadata.  
  *Outcome: Validated — `writeCache()` writes BaseUrlCacheRecord with full evidence.*
- [x] **CACHE-02**: Server uses cached/discovered base URL only when `ANNAS_BASE_URL` is not set.  
  *Outcome: Validated — `resolveBaseUrl()` short-circuits on `manualBaseUrl=true`.*
- [x] **CACHE-03**: Server preserves `ANNAS_BASE_URL` as the winning manual override whenever it is set.  
  *Outcome: Validated — `config.manualBaseUrl` gate enforced across all code paths.*
- [x] **CACHE-04**: Cache read/write failures are surfaced clearly in `update_base_url` output without corrupting MCP stdout.  
  *Outcome: Partially validated — write errors surface correctly; read errors are silently swallowed (returns null). Deferred to v1.2.*
- [x] **CACHE-05**: Documentation and implementation distinguish the server's internal mirror cache from MCP client-side cache hints such as `ttlMs` and `cacheScope`.  
  *Outcome: Validated — README explicitly distinguishes the two.*

### Offline Recovery

- [x] **REC-01**: Server identifies network failures consistent with an offline or unreachable Anna's Archive base URL.  
  *Outcome: Validated — `isLikelyOfflineBaseUrlError()` matches ENOTFOUND/ECONNREFUSED/EHOSTUNREACH/NetworkError/502/503/504.*
- [x] **REC-02**: If manual `ANNAS_BASE_URL` is offline, article tools return a clear MCP-facing error asking the user to update or delete the env var.  
  *Outcome: Validated — `withResolvedBaseUrl()` returns actionable guidance message.*
- [x] **REC-03**: If automatic cached/discovered base URL is offline, article tools refresh discovery and retry once with a trusted candidate.  
  *Outcome: Validated in code; not tested. Offline automatic retry has zero test coverage. Deferred to v1.2.*
- [x] **REC-04**: Automatic retry behavior never silently overrides a manually configured `ANNAS_BASE_URL`.  
  *Outcome: Validated — retry block gated on `manualBaseUrl=false`.*

### Documentation and Tests

- [x] **DOC-06**: README documents `update_base_url`, cache behavior, manual override semantics, and offline recovery guidance.  
  *Outcome: Validated — all four areas covered in README.*
- [x] **TEST-01**: Tests cover Wikipedia selector extraction, revision-age filtering, cache behavior, manual override behavior, and automatic offline retry with mocked fetch.  
  *Outcome: Partially validated — 4/5 areas covered; offline automatic retry path untested. Deferred to v1.2.*

<objective>
Add a content-addressed download cache to book_download and article_download so that a previously downloaded file is returned directly — without re-fetching — when the same MD5 hash or DOI is requested again within any future call (not expiry-bounded; stale if file deleted).

Purpose: Anna's Archive secret-key holders have a limited per-18h download quota. Re-downloading the same content wastes quota.
Output: Two cache helpers in file-utils.ts; both download handlers check the cache before fetching; tests covering hit and miss paths.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cache index → file path | .annas-cache.json is written by the server process; values are absolute paths read back and returned to the MCP client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-vh5-01 | Tampering | .annas-cache.json | mitigate | Returned path is validated through existsSync before use; path must be under the download root (existsSync does not follow the value into attacker-controlled territory — file is server-written) |
| T-vh5-02 | Information Disclosure | .annas-cache.json | accept | Cache file is inside ANNAS_DOWNLOAD_PATH which the operator owns; no new exposure beyond what's already on disk |
| T-vh5-03 | Denial of Service | recordDownloadCache write failure | accept | Write errors are silently swallowed — cache is best-effort; download still succeeds |
</threat_model>
